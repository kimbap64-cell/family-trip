# 업데이트·이력 설계 (2026-09-26)

사용자 요구: "업데이트돼도 기존 추천 리스트가 사라지지 않고, 리뉴얼·신규 오픈이 반영되며 목록이 이력처럼 늘어나는 느낌."

## 원칙
1. **지우지 않는다.** 한 번 목록에 오른 장소는 `data/registry.json` 에 영구 기록된다(키 = `범위:네이버place_id`, 이름이 바뀌어도 같은 장소).
2. **사라지는 것 대신 상태가 바뀐다.** `active`(점검 목록에 있음) / `missing`(이번 점검 목록에서 빠짐 — 순위 밀림 등, 폐업 아님) / `closed`(폐업·영업종료 신호).
3. **모든 변화는 날짜 있는 이벤트로 남는다.** `baseline`(기록 시작 시점) · `new`(새로 목록에 들어옴) · `tier`(추천↔조건부↔근거부족) · `rating`(별점 ±0.1) · `renamed`(이름 변경 = 리뉴얼·상호 변경 가능) · `missing`/`back` · `closed`/`reopened`.
4. **새 장소는 바로 추천하지 않는다.** 발굴되면 '검토 대기(pending)'로만 보이고, 후기·카카오 근거를 읽고 점수화된 뒤에야 추천 목록에 오른다(근거 없는 추천 금지 규칙과 동일).
5. **기록 시작 시점 목록은 baseline** 이라 전부 '새로 추가'로 뜨지 않는다. 그 뒤에 들어온 곳만 🆕 배지(30일).

## 흐름 (매주 금요일 08시 GitHub Actions → `tools/weekly_run.py`)
```
refresh_status  (기존 장소 별점·리뷰·영업상태 재조회)
 → pilot_score ×3 (점수·등급 재계산)
 → registry.py   (오늘 결과 vs 이력 비교 → 이벤트 기록)
 → discover_new.py (발굴 검색어를 새로 조회 → 이력·'이미 본 후보'에 없는 장소 = 검토 대기, 이름 바뀐 장소 = renamed)
 → build_site → verify → 커밋 → 카톡(변화 한 줄 요약)
```
- 발굴이 막혀도(차단·캡) 점검·사이트 갱신은 계속(경고만). 발굴은 목록 검색 ~51건뿐(상세·블로그 안 읽음).
- '이미 본 후보' = 첫 발굴(2026-09-26) 때 기준을 통과한 574곳(점검 대상 45+45+25 밖의 미평가 후보 포함). 이 목록에 없다가 나타난 곳이 진짜 새 후보(신규 오픈 또는 리뷰 기준을 새로 넘은 곳).
- 검토 대기 → 목록 승격은 수집 단계(`run_all.py --fetch` / Claude 세션 "이어서 해줘")에서 블로그·카카오 근거를 읽고 점수화. 승격되면 `new` 이벤트 + 🆕 배지.

## 화면
- 카드: 🆕 새로 추가(30일) 배지, 등급 변화 배지, 카드 안 '이력' 목록(최근 4건).
- **🕘 이력 탭**: 최근 60일 변화 · 새로 발견(검증 전) · 목록에서 빠진 곳/문 닫은 곳(보관). 
- 카톡: 주간 추천 아래 한 줄 `🕘 새 후보 N · 등급 변화 M …`.

## 한계 (숨기지 않는다)
- 신규 오픈일은 모른다 — '처음 우리 기준을 통과한 날'을 기록할 뿐(리뷰 300건 미만인 신규 매장은 아직 안 보임).
- 리뉴얼 = 이름 변경으로만 감지. 이름 그대로 리뉴얼한 곳은 별점·후기 변화(rating/tier 이벤트)로 간접 확인.
- 이력은 2026-09-26부터 쌓임(과거 이력은 없음).
- 이력 데이터가 커지면(이벤트 장소당 최대 40건 유지) 오래된 것부터 자른다.
